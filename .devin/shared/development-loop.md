# Development loop

Use the [ported workflow](../skills/using-development-skills/SKILL.md) for
execution and approval. Referenced team standards supply the target technical
contract when a maintenance or observability skill is explicitly invoked.

## Standards gate

Read project instructions, relevant technical references and the existing
implementation before editing. Apply standards within the task's approved
scope. New code follows the agreed contract; a bug fix or feature does not
authorize a repository-wide migration. A requested alignment may inspect the
whole named target, but changes require the approved plan.

Report conflicts between team standards and project decisions, including
architecture, release tooling and test execution. Do not silently replace a
working convention. Resolve consequential choices before implementation.
Requests for adjacent maintenance need a separate scope decision.

Preserve the approved ticket-execution rule and project delegation permissions.
Chronicles are optional; existing specifications, manuals and decision records
can carry decisions. Suggested install, cleanup, tag or push commands in
technical references do not grant authority to execute them.
