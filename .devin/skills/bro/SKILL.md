# Bro

With no argument after an answer, explain that answer again in simpler language.
Otherwise explain the supplied topic or text. Ask for the target only when it
cannot be identified from the conversation.

Follow the project's communication style. Start with what happens and why it
matters, then add only the technical detail needed to understand it. Use common
words, define unfamiliar terms and use a short example when it helps. Preserve
requirements, qualifications, uncertainty and useful technical names.

Change the explanation rather than repeating the same wording with synonyms.
Do not become patronizing, add forced slang or assume the user lacks expertise.
Do not impose a formal controlled-language standard.

Keep this a targeted re-explanation. Do not edit files, launch agents, start a
quiz or create an understanding record unless separately requested.
